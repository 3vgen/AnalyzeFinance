# Контекст проекта

Главная онбординг-заметка. Начинать чтение базы знаний нужно отсюда: здесь суть проекта, маршрут по заметкам и все договорённости. Следующий агент читает её первой и получает полный контекст для проектирования и разработки.

## Суть проекта

Мультипользовательский **Python-сервис для анализа личных финансов** (API + веб-интерфейс). Пользователь ведёт счета и транзакции, импортирует банковские выписки, а сервис категоризирует операции и считает финансовые метрики: [[Кэшфлоу]], [[Сберегательная норма]], [[Чистый капитал]], [[Финансовая подушка]], анализирует [[Расход|расходы]] и помогает с [[Бюджет|бюджетом]] и [[Финансовые цели|целями]].

## Структура базы знаний

- `00-MOC` — хабы навигации (карты содержания)
- `10-Концепции` — финансовая модель (сущности)
- `20-Методы` — методики и метрики
- `30-Данные` — данные, модель, импорт, валюты
- `40-Проект` — продукт, статус, roadmap, онбординг
- `45-Архитектура` — стек, архитектура, решения
- `50-Справочники` — глоссарий
- `Home.md` — корень графа

## Правила поддержки базы знаний

- Язык содержимого — русский.
- Каждая заметка имеет YAML-frontmatter с `tags`.
- Связи только через wiki-ссылки (двойные квадратные скобки вокруг названия заметки) — это формирует граф Obsidian.
- Имя файла = название заметки, папка — по смыслу из структуры выше.
- Новая заметка обязана ссылаться минимум на одну существующую, иначе она «выпадает» из графа.
- Новые архитектурные решения оформлять в [[Журнал решений]], статус обновлять в [[Статус проекта]].
- После добавления заметок проверять, что нет битых ссылок.

## Договорённости по git

- Коммиты делать сразу после завершения логического блока, без запроса пользователя.
- Сообщения коммитов — краткие, на русском или английском, по смыслу изменения.
- Перед коммитом проверять `git status` и `git diff`, коммитить только относящиеся к задаче файлы.
- Ветка по умолчанию — `main`, удалённый репозиторий — `origin`.
