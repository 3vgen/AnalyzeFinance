# Контекст проекта

Заметка для быстрого входа в проект — в первую очередь для следующего агента/разработчика. Здесь собрано состояние проекта, договорённости и куда смотреть дальше.

## Что за проект

Python-сервис для анализа личных финансов. Он должен импортировать финансовые данные, категоризировать их и считать метрики (кэшфлоу, сберегательную норму, чистый капитал, подушку).

- Подробное описание продукта — [[Продукт]]
- План работ — [[Roadmap]]

## Как устроена база знаний

- `Home.md` — корень графа, точка входа
- `00-MOC` — хабы навигации по областям
- `10-Концепции` — финансовая модель (сущности)
- `20-Методы` — методики и метрики
- `30-Данные` — модель данных, импорт, валюты
- `40-Проект` — продукт, roadmap, этот документ
- `50-Справочники` — глоссарий

Перед началом работы агент должен прочитать: `Home`, `00-MOC/*`, а также [[Продукт]], [[Модель данных]] и [[Roadmap]].

## Правила поддержки базы знаний

- Язык содержимого — русский.
- Каждая заметка имеет YAML-frontmatter с `tags`.
- Связи только через wiki-ссылки (двойные квадратные скобки вокруг названия заметки) — это формирует граф Obsidian.
- Имя файла = название заметки (без лишних слов), папка — по смыслу из структуры выше.
- Новая заметка обязана ссылаться минимум на одну существующую, иначе она «выпадает» из графа.
- После добавления заметок проверять, что нет битых ссылок.

## Договорённости по git

- Коммиты делать сразу после завершения логического блока, без запроса пользователя.
- Сообщения коммитов — краткие, на русском или английском, по смыслу изменения.
- Перед коммитом проверять `git status` и `git diff`, коммитить только относящиеся к задаче файлы.
- Ветка по умолчанию — `main`, удалённый репозиторий — `origin`.

## Технический контур (намерения)
