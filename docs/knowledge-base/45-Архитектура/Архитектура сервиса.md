# Архитектура сервиса

Целевая архитектура Python-сервиса анализа личных финансов. Документ описывает намерения и границы; детальное проектирование — задача следующего агента.

## Ключевые требования (влияют на архитектуру)

- Мультипользовательский сервис, данные одного пользователя изолированы — см. [[Пользователи и доступ]]
- API + веб-интерфейс (см. [[Технологический стек]])
- Работа с историческими финансовыми данными и их [[Импорт выписок|импортом]]
- Расчёт метрик ([[Кэшфлоу]], [[Сберегательная норма]], [[Чистый капитал]]) на лету

## Принципы

- **Изоляция данных**: каждый запрос финансовых данных ограничен владельцем (`owner_id`), фильтрация на уровне репозитория/сервиса, а не в UI.
- **Хранение денег**: исходная сумма и валюта операции сохраняются как есть; пересчёт — только в аналитике (см. [[Валюты]]).
- **Идемпотентность импорта**: повторный [[Импорт выписок|импорт]] не создаёт дубликатов.
- **Аудит**: финансовые записи не удаляются физически без необходимости — лучше помечать (архив/корректировка).
- **Отчёты считаются кодом**, а не SQL-запросами в обход сервисов.

## Открытые вопросы (для этапа проектирования)

- Структура кода: монолит с модулями vs. пакеты.
- Схема API первого релиза (какие эндпоинты нужны на MVP).
- Выбор SPA-фреймворка для веб-интерфейса.
