# Модель данных

Схема хранения в PostgreSQL. Реализация — SQLAlchemy 2 (ORM-модели в `testfinance/models`) + Alembic для миграций (см. [[Технологический стек]], ADR-001). Структура БД описана также в [[Схема базы данных]].

## Сущности этапа 1

| Таблица | Модель | Назначение | Связи |
| --- | --- | --- | --- |
| `users` | `User` | Пользователи (владельцы данных) | 1→N: счета, категории, транзакции |
| `currencies` | `Currency` | Каталог валют (ISO 4217) | справочник |
| `exchange_rates` | `ExchangeRate` | Курсы base→quote на дату | → currencies |
| `accounts` | `Account` | Счета пользователя | → users, currencies; 1→N транзакции |
| `categories` | `Category` | Дерево категорий | → users; само-ссылка `parent_id` |
| `transactions` | `Transaction` | Движения денег (ядро) | → users, accounts, categories, currencies |

Подробности по каждой таблице — в [[Схема базы данных]].

## Ключевые соглашения

- **Первичные ключи** — UUID для бизнес-сущностей (`users`, `accounts`, `categories`, `transactions`), естественный ключ для справочников (`currencies.code`) — ADR-005.
- **Владелец**: каждая финансовая таблица содержит `owner_id` → изоляция по пользователю (см. [[Пользователи и доступ]], ADR-003).
- **Деньги** — `NUMERIC(19,4)`; сумма хранится в валюте операции без пересчёта (ADR-004). Валютный код хранится рядом с суммой.
- **Категории** — дерево через `parent_id` (adjacency list).
- **Знак суммы**: положительная — доход, отрицательная — расход.
- **Аудит**: удаление через `is_archived`/`ON DELETE SET NULL`, а не физическое стирание истории.
- **Импорт**: поле `external_id` + уникальный индекс на (account, external_id) — дедупликация при повторном импорте.
